## 一、页面结构概览

Dashboard 是一个浏览器新 Tab 打开的全屏 SPA（单页应用），URL 形如 `chrome-extension://<extension-id>/dashboard.html`。整体由四层组成：

| 层 | 内容 | 是否常驻 |
|---|---|---|
| **顶部导航栏** | Logo + 三个 Tab 切换 + AI Key 状态指示 + 诊断入口 | 常驻 |
| **主内容区** | 三个 Tab 视图之一 | 切换 |
| **底部状态条** | 抓取进度 / 暂停 / 完成 提示 | 仅抓取过程显示 |
| **全局弹窗层** | 模态弹窗 + Toast 通知 | 按需 |

**三个 Tab：**

```
┌─────────────────────────────────────────────────────────┐
│  📡 xhs-radar    [配置] [展示] [收藏与历史]    🔑✅ 🛠 │  ← 顶部导航
├─────────────────────────────────────────────────────────┤
│                                                         │
│            ┌────────────────────────┐                   │
│            │    主内容区（Tab）     │                   │
│            └────────────────────────┘                   │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  ⏳ 抓取中... 137 / 200 候选 · 已识别爆款 8 条   ⏸ 暂停 │  ← 底部状态条
└─────────────────────────────────────────────────────────┘
```

**Tab 默认顺序：** 首次打开 → 配置 Tab；抓取完成后 → 自动切到展示 Tab；其他时候用户手动切换。

**URL Hash 路由：**
- `#config`（默认）
- `#display`
- `#favorites`（默认子页签）
- `#history`

## 二、各区块详细说明

### 2.0 顶部导航栏（常驻）

**展示内容：**
- 左：Logo（📡 雷达图标） + 文字 "xhs-radar"
- 中：三个 Tab 按钮 — 配置 / 展示 / 收藏与历史
- 右：① AI Key 状态指示（🔑✅ 已配置 / 🔑⚠️ 未配置 / 🔑⏳ 测试中）；② 诊断模式按钮 🛠

**交互规则：**

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户点击 Tab 按钮 | 切换主内容区 + 更新 URL Hash | 选中 Tab 高亮，其他 Tab 灰色 |
| 用户点击 AI Key 指示器 | 跳转到配置 Tab 的"AI Key"区块并自动滚动到该锚点 | 配置 Tab 激活 + 高亮 AI Key 输入框 |
| 用户点击诊断按钮 | 弹出诊断模式弹窗（见 §5.7） | 弹窗显示当前接口拦截状态 |

**状态对应：**
- AI Key 已配置且测试通过 → 🔑✅ 绿色
- AI Key 未配置 或 测试失败 → 🔑⚠️ 黄色
- 正在测试 → 🔑⏳ 旋转动画

### 2.1 配置 Tab（`#config`）

**区块 A：关键词组**

展示：输入框 + 已添加关键词 chip 列表 + 计数 "x/10"

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户在输入框输入字符并按 Enter 或逗号 | 校验长度 1–30 | 通过：清空输入框 + 追加 chip；不通过：输入框红框 + 文字"关键词长度需 1–30 字" |
| 用户点 chip 上的 × | 从列表移除该关键词 | chip 消失 + 计数 -1 |
| 关键词数量已达 10 | 输入框 disabled + 灰色提示"已达上限 10 个" | 用户需先删除才能继续添加 |
| 关键词数量为 0 | 底部"开始抓取"按钮 disabled + tooltip"请至少添加 1 个关键词" | 不允许触发抓取 |

**区块 B：时间窗口**

展示：单选组（近 3 天 / 近 7 天 / 近 30 天 / 自定义） + 自定义模式下展开日期范围选择器

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户切换到"自定义" | 展开开始日 / 结束日两个日期选择器 | 默认值：开始 = 今天 -7、结束 = 今天 |
| 用户选起止日期 | 校验跨度 ≤ 365 天 + 起止顺序 | 不通过：日期框红框 + 文案"日期范围需 ≤ 365 天" |
| 用户切回预设选项 | 收起自定义日期选择器 | 自定义日期清除 |

**区块 C：爆款阈值（可调）**

展示：两个数字输入框

| 字段 | 默认值 | 范围 | 输入步进 |
|---|---|---|---|
| 综合评分（CES）阈值 | 100 | 10–100,000 | 10 |
| 点赞/粉丝比阈值 | 0.5（=50%） | 0.01–10 | 0.05 |

**交互：**
- 用户改值 → 校验范围 → 通过：保存 + 更新预览（如果当前展示 Tab 有数据，列表会重新过滤）；不通过：红框 + 提示

**区块 D：目标爆款数**

展示：数字输入框 + 滑块（1–100） + 默认 20

**交互：** 用户改值 → 校验 1 ≤ N ≤ 100 → 实时同步输入框与滑块

**区块 E：候选池上限**

展示：单选 200（推荐） / 250 / 300（最大） + 提示"候选池越大触发风控概率越高，建议从 200 起步"

**交互：** 用户切选项 → 直接保存

**区块 F：AI Key（DeepSeek）**

展示：
- 密码型输入框（默认遮罩，旁边 👁 图标可显示明文）
- "测试 Key" 按钮
- 模型选择下拉：deepseek-chat（默认）/ deepseek-reasoner
- 帮助链接"如何获取 DeepSeek API Key"（指向 platform.deepseek.com）

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户填 Key 并失去焦点 | 仅本地存储到 chrome.storage.local，不联网 | 顶部 Key 状态指示变 🔑⚠️（未测试） |
| 用户点"测试 Key" | 用最便宜的 deepseek-chat 发一句"hi"消息 | 成功：状态变 🔑✅ + Toast"Key 有效"；失败：状态变 🔑⚠️ + Toast"Key 无效或网络错误：xxx" |
| 用户点 👁 | 切换 Key 显示遮罩 ↔ 明文 | 图标在 👁 ↔ 🙈 切换 |

**区块 G：开始抓取按钮（粘性底部）**

展示：大主按钮"开始抓取" + 当前配置摘要小字"(关键词: AI 工具,Claude · 近 7 天 · 目标 20 条)"

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 关键词 ≥ 1 且时间窗口已选 | 按钮 enabled | 主色（红） |
| 关键词 = 0 或时间窗口缺失 | 按钮 disabled | 灰色 + tooltip 说明缺失项 |
| 用户点击按钮 | ① 检查是否已有未保存的批次 → 弹窗确认（见 §5.1）；② 检查小红书登录态 → 未登录则弹窗（§5.2）；③ 通过则触发抓取流程 + 切到展示 Tab + 显示底部状态条 | 见 §4 抓取状态机 |

### 2.2 展示 Tab（`#display`）

**进入条件：** 当前批次抓取完成 或 用户从历史批次载入。无可用批次时展示空状态（见 §4.1）。

**区块 A：批次信息条（顶部）**

展示：
- 批次时间 + 关键词列表 + "候选 187 / 爆款 18 / 未达标 5"
- 右侧两个按钮："另开新批" / "重新抓取"

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户点"重新抓取" | 弹窗确认覆盖当前批次 → 确认后用同样的配置重抓 | 当前批次进入历史，新批次开始抓 |
| 用户点"另开新批" | 跳到配置 Tab | 配置 Tab 激活，可改配置后开始 |

**区块 B：筛选与排序栏**

展示：
- 排序下拉：综合评分 ↓（默认）/ 点赞 ↓ / 收藏 ↓ / 评论 ↓ / 发布时间 ↓
- 筛选下拉：全部 / 仅爆款 / 仅未达标
- 角度聚类筛选 chip 组（仅当用户已触发"角度聚类 AI"后才显示）

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户改排序 | 列表客户端重新排序（不重抓） | 列表瞬时更新 |
| 用户改筛选 | 列表客户端过滤 | 列表瞬时更新 |
| 用户点角度筛选 chip | 列表过滤至该角度 + 该 chip 高亮 | 多选模式：再点取消 |

**区块 C：爆款列表（卡片网格）**

每条笔记一张卡片，字段如下：

| 字段位置 | 字段 | 来源 |
|---|---|---|
| 卡片左上 | 缩略图占位（一期不抓图片，统一占位 emoji 📄） | — |
| 卡片标题 | 笔记标题 | 搜索接口 |
| 标题下 | 博主昵称 + 粉丝数 | 搜索接口 + 用户主页接口 |
| 中部 | 互动数 4 项：👍 点赞 / ⭐ 收藏 / 💬 评论 / 🔁 分享 | 搜索接口 |
| 右上 | 综合评分（大字 + 颜色编码） | 本地计算 |
| 右上下方 | 状态标签：🔥 爆款 / 📄 未达标 | 本地计算 |
| 卡片底部 | 操作：⭐ 收藏 / 📖 查看正文 / 🔗 在小红书打开 | — |

**颜色编码：** CES ≥ 阈值 × 2 红色；阈值 ≤ CES < 阈值 × 2 橙色；CES < 阈值 灰色。

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户点"查看正文" | ① 检查本地是否已有该笔记的 desc → 没有则调详情接口（见 §7.2）；② 展开右侧详情抽屉 | 详情抽屉滑入 + 卡片高亮 |
| 用户点"⭐ 收藏" | 写入收藏库 + 卡片角标变实心 ⭐ | Toast"已加入收藏" |
| 用户点"在小红书打开" | 在新 Tab 打开 `https://www.xiaohongshu.com/explore/<note_id>?xsec_token=<...>` | 新 Tab |

**区块 D：详情抽屉（右侧 40% 宽，可关闭）**

展示：
- 顶部：标题 + 元数据（博主、发布时间、互动数、综合评分）
- 主体上方：原话题标签 chip 列表
- 主体：完整正文（来自详情接口的 desc 字段）
- 底部 4 个 AI Tab：选题建议 / 结构拆解 / 角度聚类 / 趋势词

**AI Tab 各自的状态规则：**

| AI Tab | 范围 | 默认状态 | 触发 | 输出 |
|---|---|---|---|---|
| 选题建议 | 全局（基于全部爆款） | 占位"点击下方按钮分析当前批次的选题方向" | 用户点"分析"按钮 → 调 DeepSeek 一次 | 5 个候选选题（每个含一句话角度 + 关联的爆款 ID 列表） |
| 结构拆解 | 单条（当前打开的笔记） | 占位"点击下方按钮拆解这条笔记的写作结构" | 用户点"拆解"按钮 → 调 DeepSeek 一次 | 4 段：标题钩子 / 开头 / 正文结构 / 结尾 CTA |
| 角度聚类 | 全局 | 占位"点击下方按钮按角度对全部爆款聚类" | 用户点"聚类"按钮 → 调 DeepSeek 一次 | 角度列表（教程/测评/故事/清单等），每个角度含笔记 ID 数组 + 占比 |
| 趋势词 | 全局 | 占位"点击下方按钮提取赛道高频词与话题标签" | 用户点"提取"按钮 → 调 DeepSeek 一次 | 高频词云 + 话题标签 Top 20 |

**AI Tab 五状态：**

| 状态 | UI |
|---|---|
| 未触发 | 占位文字 + 触发按钮 |
| 加载中 | spinner + "AI 分析中..." |
| 成功 | 结构化展示结果 + 右上角 ↻ 重新生成按钮 |
| 失败（首次） | 自动重试 1 次 |
| 失败（重试后） | 红色提示卡 + 错误详情 + "检查 Key" 链接 → 跳转配置页 |

**全局 AI 缓存：** 选题建议 / 角度聚类 / 趋势词 三个全局 AI 一旦成功，结果缓存到当前批次（chrome.storage），同一批次切回后直接显示。

### 2.3 收藏与历史 Tab（`#favorites` / `#history`）

子 Tab 切换：收藏（默认） / 历史批次

#### 2.3.1 收藏子 Tab

展示：列表视图（不是卡片网格，更紧凑），每行一条收藏笔记。

字段：标题 + 博主 + 互动数 + 综合评分 + 收藏时间 + 来源批次 ID + 操作

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|
| 用户点行中的"查看正文" | 弹出详情抽屉（同 2.2 区块 D） | 抽屉滑入 |
| 用户点"取消收藏" | 弹窗确认（§5.5） → 确认后从收藏库移除 | 该行消失 + Toast"已取消收藏" |
| 用户点"跳到原批次" | 切到展示 Tab + 载入该笔记所属的历史批次 + 在列表中高亮该笔记 | 展示 Tab 激活 |
| 收藏数 = 0 | 显示空状态（§4.1） | "还没有收藏任何笔记" |

#### 2.3.2 历史批次子 Tab

展示：列表视图，每行一个批次。

字段：批次 ID（短哈希）+ 创建时间 + 关键词 + 候选数 + 爆款数 + 操作

| 触发条件 | 执行动作 | 结果状态 |
|---|---|---|

| 历史数已达 10 + 用户开始新批次 | 自动删除最旧批次 + Toast"最旧批次已自动清理" | 始终保留最近 10 次 |

## 三、字段与数据来源

### 3.1 笔记字段（一条爆款的完整数据结构）

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `note_id` | string | 搜索接口 | 笔记唯一 ID |
| `xsec_token` | string | 搜索接口 | 详情接口的访问 token，必须随请求带 |
| `model_type` | enum | 搜索接口 | "note" / "video" / "ad"，本工具仅保留 note |
| `title` | string | 搜索接口 | 标题（可能为空，用 desc 前 30 字回退） |
| `desc` | string | 详情接口（懒加载） | 正文，仅对爆款抓 |
| `time` | timestamp(ms) | 搜索接口 | 发布时间 |
| `last_update_time` | timestamp(ms) | 搜索接口 | 最后更新时间 |
| `tag_list` | array<{type, name}> | 搜索接口 / 详情接口 | 话题标签 |
| `user.user_id` | string | 搜索接口 | 博主 ID |
| `user.nickname` | string | 搜索接口 | 博主昵称 |
| `user.avatar` | string | 搜索接口 | 博主头像 URL |
| `user.fans` | number | 用户主页接口（懒加载） | 粉丝数；按 user_id 缓存避免重复请求 |
| `interact_info.liked_count` | string→number | 搜索接口 | 点赞数；可能是 "1.2万" 等字符串，需解析 |
| `interact_info.collected_count` | string→number | 搜索接口 | 收藏数 |
| `interact_info.comment_count` | string→number | 搜索接口 | 评论数 |
| `interact_info.share_count` | string→number | 搜索接口 | 分享/转发数 |

### 3.2 本地计算字段（不来自任何接口，由判定模块计算）

| 字段 | 公式 | 说明 |
|---|---|---|
| `ces_score` | `liked × 1 + collected × 1 + comment × 4 + share × 4` | CES 综合评分（关注权重 × 8 一期不算，因关注数前端拿不到） |
| `like_to_fans_ratio` | `liked / max(fans, 1)` | 点赞 / 粉丝比 |
| `days_since_publish` | `(now - time) / 86400000` | 发布至今天数 |
| `time_decay_factor` | `exp(-0.1 × days_since_publish)` | 时间衰减系数（半衰期约 7 天） |
| `weighted_score` | `ces_score × time_decay_factor` | 用于排序的最终分 |
| `is_bomb` | `ces_score ≥ ces_threshold && like_to_fans_ratio ≥ ratio_threshold` | 是否爆款 |

### 3.3 用户配置字段（chrome.storage.local，键名 `user_config`）

| 字段 | 类型 | 默认值 |
|---|---|---|
| `keywords` | string[] | [] |
| `time_window` | "3d" / "7d" / "30d" / `{start, end}` | "7d" |
| `ces_threshold` | number | 100 |
| `like_ratio_threshold` | number | 0.5 |
| `target_bomb_count` | number | 20 |
| `candidate_pool_max` | 200 / 250 / 300 | 200 |
| `deepseek_api_key` | string（加密存储） | "" |
| `deepseek_model` | "deepseek-chat" / "deepseek-reasoner" | "deepseek-chat" |

### 3.4 批次数据结构（chrome.storage.local，键名 `batches`）

```
{
  batch_id: string (uuid),
  created_at: timestamp,
  keywords: string[],
  time_window: ...,
  thresholds: { ces, like_ratio },
  candidate_count: number,
  bomb_count: number,
  notes: NoteRecord[],         // 全部候选（含 ces_score 等本地计算字段）
  ai_results: {                 // 缓存 AI 输出
    topic_suggestions?: object,
    angle_clusters?: object,
    trend_keywords?: object,
  },
  status: "running" | "complete" | "stopped" | "failed"
}
```

### 3.5 收藏库结构（chrome.storage.local，键名 `favorites`）

```
{
  [note_id]: {
    note_id, title, user, interact_info, ces_score,
    favorited_at: timestamp,
    source_batch_id: string
  }
}
```

## 四、状态与边界条件

### 4.1 全局五状态

| 状态 | UI 反馈 | 备注 |
|---|---|---|
| 加载中 | 中央 spinner + 文字"加载中..." | 仅初次进 Tab、抓正文等场景 |
| 错误 | 红色提示卡 + 错误信息 + 重试按钮 | 文字明确（不写"出错了"，要写"无法连接 DeepSeek，请检查网络"等） |
| 空 | 居中插画 + 引导文案 + 主行动按钮 | 见各 Tab 空状态文案 |
| 权限不足 | 黄色卡 + 引导文案 | 仅当 Chrome 拒绝 host_permissions 时 |
| 风控暂停 | 顶部黄色横条 + 弹窗（§5.3） | 抓取过程中专用 |

### 4.2 各 Tab 空状态文案

| Tab | 触发 | 文案 |
|---|---|---|
| 配置 | — | 配置页本身无空状态，始终显示表单 |
| 展示 | 无任何批次 | "还没抓过任何赛道。回到配置页设定关键词、点击「开始抓取」。" + 跳转按钮 |
| 收藏 | 收藏数 = 0 | "还没有收藏任何笔记。在展示页看到喜欢的爆款，点 ⭐ 加入收藏。" |
| 历史 | 历史数 = 0 | "还没有历史批次。每次抓取完成后会自动保存到这里。" |

### 4.3 抓取状态机

```
IDLE
  │ 用户点"开始抓取"
  ▼
VALIDATING （检查登录态）
  │            └→ NOT_LOGGED_IN → 弹窗 §5.2 → 用户登录 → 回 VALIDATING
  ▼
SCRAPING （后台 Tab 滚动 + 拦截响应）
  │  ├→ CAPTCHA → 弹窗 §5.3 → 用户过验证 → 回 SCRAPING
  │  └→ 候选池满 / 爆款达标 / 用户点"暂停"
  ▼
DETAIL_FETCHING （仅对爆款抓正文）
  │  └→ 接口失败 → 重试 1 次 → 仍失败则跳过该条 + 标注"正文获取失败"
  ▼
COMPLETE （切到展示 Tab + 持久化批次）
```

**异常分支：**
- 任何阶段断网 → 进入 FAILED → 弹窗"网络异常，已抓取 N 条已保存为草稿批次" + 选项"重试 / 保留进度退出"
- 用户主动关闭 Dashboard Tab → 抓取继续在后台进行（service worker），下次打开 Dashboard 自动恢复显示
- 抓满候选池上限仍未达爆款目标 → 切到 COMPLETE，但批次状态条标注"未达爆款标准"，提供"继续找"按钮（再抓一轮，候选池上限 +100）

### 4.4 边界条件清单

| 场景 | 行为 |
|---|---|
| 关键词重复 | 自动去重（前端校验，输入时若已存在则提示） |
| 时间窗口跨度 0 天（同一天） | 视为有效，但提示"时间窗口较短可能候选过少" |
| 同一作者多条爆款 | 合法保留；粉丝数请求按 user_id 去重 |
| 笔记 desc 为空（视频笔记或纯图笔记） | 一期标注"该笔记无文字正文"，AI 拆解时跳过 |
| 详情接口返回 404 / 笔记已删除 | 标注"已不可访问"，从爆款列表移除但保留在 raw 数据 |
| 用户改阈值后展示 Tab 数据被重新筛选 | 仅修改 is_bomb 标记，不重新抓取；所有候选保留 |
| 候选池中 0 条达标但目标爆款 ≥ 1 | 兜底返回综合评分 Top N 条，全部标注"未达爆款标准" |
| 用户在抓取中切到其他 Tab | 抓取继续；底部状态条仍可见 |
| 同一笔记因不同关键词被抓多次 | 按 note_id 去重，保留首次出现的关键词来源 |
| 浏览器 storage 写入失败（quota exceeded） | 弹窗"存储空间不足，请删除部分历史批次或导出后清理" + 跳转历史 Tab |

## 五、弹窗与流程说明

### 5.1 开始抓取确认弹窗

**触发：** 用户点"开始抓取"按钮，且当前已有未保存的展示批次。
**内容：** "当前批次（关键词：xxx，爆款 N 条）将被存入历史。是否开始新批次？"
**选项：** 取消 / 开始
**结果：** 选"开始" → 当前批次入历史 + 进入抓取流程

### 5.2 未登录小红书提示弹窗

**触发：** 抓取流程检测到当前浏览器无小红书登录态（cookie 中无 `web_session`）。
**内容：** "需要登录小红书才能抓取数据。" + 二次说明"插件不会读取你的密码，只在你已登录的会话下读取笔记数据。"
**选项：** 取消 / 跳转登录
**结果：** 选"跳转登录" → 在新 Tab 打开 `https://www.xiaohongshu.com/login`，关闭 Tab 后回到 Dashboard 自动重试一次登录态检测

### 5.3 风控验证码暂停弹窗

**触发：** 抓取过程中检测到小红书页面出现验证码（DOM 中出现验证码组件 / 接口返回 461 等）。
**内容：** "小红书要求验证身份。请在小红书 Tab 中手动通过验证后，点「我已通过」继续。"
**选项：** 我已通过（继续抓取） / 暂停批次（保存当前进度）
**结果：**
- 选"我已通过" → 1 秒后再次发出搜索请求 → 若仍报验证码 → 此弹窗保留
- 选"暂停批次" → 进入 STOPPED 状态，结果落入历史，可后续"继续找"

### 5.4 AI Key 缺失提示弹窗

**触发：** 用户在展示 Tab 点任何 AI 触发按钮，但 AI Key 未配置或测试未通过。
**内容：** "AI 功能需要 DeepSeek API Key。"
**选项：** 取消 / 去配置
**结果：** 选"去配置" → 跳转配置 Tab AI Key 区块并高亮

### 5.5 删除确认弹窗（收藏 / 历史）

**触发：** 用户点删除按钮。
**内容：** "确认删除「xxx」？此操作不可恢复。"（xxx 替换为收藏标题或批次摘要）
**选项：** 取消 / 删除
**结果：** 选"删除" → 立即从 storage 移除 + Toast 提示

### 5.6 导出 CSV 流程

**触发：** 用户点历史子 Tab 中某批次的"导出 CSV"。
**动作：**
1. 在内存生成 CSV 字符串，列：批次时间、关键词、笔记 ID、标题、博主、粉丝数、点赞、收藏、评论、分享、CES、点赞/粉丝比、是否爆款、发布时间、笔记 URL、正文（如已抓）
2. 用 Blob + URL.createObjectURL 触发浏览器下载
3. 文件名：`xhs-radar-<批次时间>-<关键词>.csv`
**结果：** 浏览器下载完成 + Toast"已导出 N 条记录"

### 5.7 诊断模式弹窗

**触发：** 用户点顶部 🛠 图标。
**展示：**
- 当前已识别的小红书接口路径列表（最近 10 条）
- 拦截命中数 / 失败数
- "复制诊断信息" 按钮（拷到剪贴板，便于反馈给作者）
- 接口字段映射版本（如 `selectors.ts v1`）
**选项：** 关闭 / 复制
**用途：** 当小红书改版导致工具异常时，用户可快速看到失效环节

## 六、视觉规范（语义描述）

### 6.1 色彩

| 用途 | 语义 | 备注 |
|---|---|---|
| 主色 | 小红书风格的活力红 | 用于主按钮、爆款标签、当前选中 Tab |
| 强调色 | 暖橙色 | 用于"潜力"标签、提醒用户的重要数字 |
| 中性色 - 文字 | 深灰（接近黑）/ 中灰 / 浅灰 | 三级文字层次 |
| 中性色 - 背景 | 纯白 / 极浅灰 / 浅灰边框 | 卡片底色 / 区块底色 / 分隔线 |
| 状态 - 成功 | 绿 | AI Key 验证通过、Toast 成功 |
| 状态 - 警告 | 黄 | 风控暂停、AI Key 未配置 |
| 状态 - 错误 | 红（与主色区分，更深沉） | 接口失败、表单校验失败 |

### 6.2 字号梯度

- 一级：用于 Dashboard 顶部 Logo、空状态主文案（约 24–28px）
- 二级：Tab 标题、批次信息条主标题（约 18–20px）
- 三级：卡片标题、区块标题（约 16px）
- 正文：卡片字段、表单标签（约 14px）
- 辅助：粉丝数、时间戳、tooltip（约 12–13px）

### 6.3 间距与圆角

- 卡片内边距：宽松（约 16–20px）
- 区块外边距：明显分隔（约 24px）
- 卡片圆角：中等柔和（约 8–12px）
- 按钮圆角：与卡片一致

### 6.4 整体风格

- 现代克制：参考 Linear、Notion、Raycast 的设计语言
- 层次清晰：主色仅用于真正需要用户注意的元素，其余以中性色为主
- 避免过度装饰：不使用渐变背景、阴影限制在卡片浅阴影
- 动效：平滑过渡（200–250ms），不抢眼

## 七、外部接口依赖

> ⚠️ 真实接口路径与签名机制在 L3 第 4 章（API Schema）中给出，此处仅描述业务用途。

### 7.1 小红书 - 搜索笔记接口

- **用途：** 给定一个关键词、排序方式、笔记类型，返回当前页的候选笔记列表
- **业务作用：** 通过自动滚动小红书搜索页，被动拦截该接口的响应数据，累积成候选池
- **取得字段：** `note_id` / `xsec_token` / `title` / `user` / `interact_info` / `time` / `tag_list` 等
- **调用频率：** 由小红书前端控制（每次滚动触发一次），插件不主动调
- **风控敏感度：** 中（高频滚动会触发验证码）

### 7.2 小红书 - 笔记详情接口

- **用途：** 给定 note_id + xsec_token，返回笔记完整正文与详细元数据
- **业务作用：** 仅对被判定为爆款的笔记调用，避免大量请求触发限流
- **取得字段：** 主要是 `desc`（正文）；以及更完整的 `tag_list`
- **调用频率：** 由插件主动调，控制在 800–2000ms 随机延迟
- **风控敏感度：** 高（500 条全调必封；只对爆款 ≤100 条调相对安全）

### 7.3 小红书 - 用户主页接口

- **用途：** 给定 user_id，返回博主的粉丝数等基础信息
- **业务作用：** 仅对爆款候选作者调用，按 user_id 缓存，避免重复请求同一作者
- **取得字段：** `fans`（粉丝数）等
- **调用频率：** 由插件主动调，每个作者一次
- **风控敏感度：** 低

### 7.4 DeepSeek API（用户自带 Key）

- **用途：** 4 个独立 prompt，分别完成选题建议 / 单条结构拆解 / 角度聚类 / 趋势词
- **业务作用：** 4 个均按需触发，每个返回结构化 JSON，前端解析后展示
- **协议：** OpenAI Chat Completions 兼容
- **模型选择：** 默认 `deepseek-chat`；可选 `deepseek-reasoner`（推理增强，成本稍高）
- **失败策略：** 单次失败自动重试 1 次（指数退避 1s → 2s）；仍失败则提示用户检查 Key
- **token 控制：** 单次响应 max_tokens 默认 2000，足够 4 个 prompt 各自的输出
- **缓存策略：** 全局 AI（选题/聚类/趋势词）结果按批次缓存；单条 AI（结构拆解）按 note_id 缓存
- **JSON 校验：** 每个 prompt 定义明确的 JSON Schema，解析失败自动重试 1 次
